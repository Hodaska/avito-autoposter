# AGENTS.md: инструкция для ИИ-агента (Claude Code, Codex и др.)

Репозиторий: полуавтоматическая выкладка объявлений на Авито + уведомления + карта метро. Только Windows. Человек-пользователь управляет сайтом на http://127.0.0.1:7777, вы помогаете **установить, настроить, диагностировать и менять код**. Отвечайте пользователю по-русски.

## Жёсткие правила

1. **Никогда не публикуйте секреты.** Не коммитьте и не выводите `secrets/telegram.json`, токены, `settings.json`, `автовыкладка/config.json`, `profile_account/` (там сессия Авито: cookies), `data/`, фото товара. Всё это в `.gitignore`.
2. **Проверки Авито (капча, «проблема с IP», паспорт, SMS) проходит только человек.** Не автоматизируйте и не обходите их. Увидели страницу «Доступ ограничен» или логин: остановитесь, попросите пользователя показать окно и пройти проверку.
3. Скрипт **не нажимает «Продолжить» и «Опубликовать»**, не вводит адрес и не трогает Авито Доставку и ставку за просмотр: это делает человек. Не добавляйте это без прямой просьбы.
4. **Chrome профиля `profile_account` без нужды не перезапускать и не закрывать**: в нём вход в Авито и вкладка наблюдателя. Не трогайте обычный Chrome пользователя. `browser_host.kill()` убивает только процессы с `profile_account` в командной строке.
5. Не делайте лишней автоматической активности в аккаунте Авито (периодические перезагрузки, парсинг). Наблюдатель читает счётчик с уже открытой вкладки без запросов.
6. Не обещайте, что бана не будет. Автоматизация может нарушать правила Авито, пользователь это знает и берёт риск на себя.
7. Тексты объявлений должны быть правдой. Шаблон в репозитории примерный; факты о магазине и товаре подставляет владелец.
8. Не запускайте второй экземпляр сайта/наблюдателя/прокси на тех же портах (7777, 8899, 9222): сначала проверьте, что порт свободен.

## Установка с нуля (выполните по шагам и проверяйте результат)

1. Проверьте окружение: Windows 10/11, Google Chrome (`settings.json → chrome_path`, если не в стандартном месте), Python ≥ 3.10 (`py -3 --version`).
2. `powershell -ExecutionPolicy Bypass -File .\install.ps1 -DryRun`, затем без `-DryRun`. Скрипт: `.venv` + `requirements.txt`, `settings.json` и `автовыкладка\config.json` из примеров, автозапуск (задача AvitoWatch или ярлык в автозагрузке, задача AvitoGuard каждые 5 мин, ярлык сайта). Права администратора не нужны; если Планировщик отказывает (`Access denied` на триггере при входе), скрипт использует ярлык в автозагрузке.
3. Telegram (необязательно): создать бота у @BotFather, узнать `chat_id` (`getUpdates`), записать в `secrets\telegram.json` (образец `secrets\telegram.example.json`) или `-TelegramToken/-TelegramChatId` у install.ps1. Проверка: `.venv\Scripts\python.exe -c "import avito_check;print(avito_check.tg('тест'))"` из корня репозитория, должно вернуть `True`.
4. Сеть и VPN: спросите пользователя, есть ли системный VPN и просит ли Авито проверку по IP. Если нет, `settings.json → "bypass_vpn": false`. Если да, оставьте `true` (прокси `direct_proxy.py`); при ошибке определения роутера задайте `gateway`. Проверка: `.venv\Scripts\python.exe автовыкладка\direct_proxy.py` не должен падать, порт 8899 открывается; в Chrome с профилем сайт `https://api.ipify.org` должен показывать домашний IP.
5. Запустите сайт (`автовыкладка\запуск_сайта.bat`), попросите пользователя войти в Авито в показанном окне Chrome. Проверка: `http://127.0.0.1:7777/api/browser` возвращает `logged_in: true`.
6. Запустите наблюдателя: `.venv\Scripts\pythonw.exe avito_watch.py` (если не стартовал сам). Проверка: `data\avito_watch.log` содержит «подключён к Chrome», файл `data\avito_watch.alive` обновляется каждую минуту.
7. Попросите пользователя положить фото в `фото\<папка>\` (имена `1.png`, `2.jpg`…) и поправить `config.json`/`шаблон_описания.txt`. Первый прогон только на одной форме, пользователь смотрит.

## Архитектура и карта файлов

```
install.ps1 / uninstall.ps1    установка и снятие автозапуска
settings.example.json          необязательные настройки установки (bypass_vpn, gateway, chrome_path)
secrets/telegram.example.json  образец секретов Telegram (реальный файл в .gitignore)
avito_watch.py                 наблюдатель: держит Chrome, читает счётчик чатов, шлёт Telegram, чинит Chrome
avito_check.py                 библиотека: tg() (3 попытки + запасной подпроцесс + data/telegram.log), JS_COUNT, load()
avito_guard.py                 сторож (только stdlib), задача каждые 5 минут, смотрит data/avito_watch.alive
avito_direct_on/off.ps1        необязательные постоянные маршруты Авито мимо VPN (администратор)
автовыкладка/
  app.py            сайт на stdlib (http.server), порт 7777, только 127.0.0.1; API /api/config|info|status|preview|run|stop|browser
  index.html        интерфейс сайта
  filler.py         заполнение форм Авито через Playwright (CDP), STATE для сайта, Stop при любом несовпадении
  textgen.py        шаблон -> тексты пакета; подмена символов построчно уникально; варианты заголовка
  photos.py         уникализация фото (Pillow), порядок: №1 первым, остальные случайно
  browser_host.py   единый Chrome: запуск, прятать/показывать окно (ctypes user32), kill() зависшего
  direct_proxy.py   локальный HTTP/CONNECT-прокси 127.0.0.1:8899, исходящие сокеты привязаны к адресу физической сетевой карты
  settings.py       чтение settings.json, поиск chrome.exe
  cdp.py            подключение Playwright к уже открытому Chrome
  recon.py          разведка формы Авито (только чтение), для починки селекторов
  config.example.json, шаблон_описания.txt
карта_метро/        build.py + шаблон.html + метро.json -> карта.html
статистика_выкладок.пример.csv   образец таблицы просмотров
фото/<папки>/       сюда пользователь кладёт оригиналы (в git только .gitkeep)
docs/AVITO_FORM.md       путь формы Авито, data-marker, как чинить при смене вёрстки
docs/TROUBLESHOOTING.md  известные сбои и исправления
```

**Единый Chrome.** `browser_host.launch()` запускает `chrome.exe --remote-debugging-port=9222 --user-data-dir=<repo>\profile_account` (+ прокси-флаги, если `bypass_vpn`), окно сразу прячется (`ShowWindow SW_HIDE`). Сайт при открытии показывает окно (`SW_SHOW` + `SW_RESTORE`), кнопка «Я закончил работу» прячет. Окно ищется по PID главного процесса профиля, класс `Chrome_WidgetWin_1`, непустой заголовок. Нужен нестандартный `--user-data-dir`, иначе Chrome ≥ 136 не даст отладочный порт.

**Прокси мимо VPN.** Работает ОТДЕЛЬНЫМ процессом (`pythonw direct_proxy.py`), его поднимают `ensure_running()` из `browser_host.launch()`, `app.py` и каждого цикла наблюдателя. Нельзя запускать его потоком внутри наблюдателя: при падении наблюдателя Chrome остаётся с мёртвым `--proxy-server` (так уже ломалось).

**Наблюдатель.** Цикл раз в минуту: `connect_over_cdp`, вкладка `/profile/messenger`, чтение `[data-marker="header/unread-chats-counter"]` JS-ом (`JS_COUNT`), при росте числа `tg("Авито")`. Если отправка не удалась, состояние не обновляется и отправка повторяется в следующем цикле. После 5 неудачных подключений подряд при живом Chrome он убивает и перезапускает Chrome профиля. Ограничение: считается число непрочитанных *чатов*, а не сообщений; новое сообщение в уже непрочитанном чате уведомления не даст, системный чат «Авито» считается как обычный.

**Заполнение формы.** `filler.fill_one`: Ctrl+клик по `a[href="/additem"]` на главной (новая вкладка), категория «Электроника» → ввод заголовка в `#title` → подсказка «Мобильные телефоны» → поля формы по `data-marker` (подробно в `docs/AVITO_FORM.md`) → фото по одному → описание вставкой через `keyboard.insert_text` (Draft.js; при несовпадении после вставки откат на посимвольный ввод) → цена → выключение «Предложения». Любое несовпадение или капча: `Stop`, вкладка остаётся как есть.

**Тексты.** `textgen.make_batch(cfg, plan)`: шаблон → `str.format` с полями модели → построчная подмена `sub()` (а→a, е→e/E, о→o/0, з→3; слова с цифрами и `@` не трогаются) с проверкой, что строка не повторялась в пакете. Заголовок: `iPhone <модель> <память> <SIM>` и слово «новый» в одном из 10 вариантов положения.

## Как менять под другой товар

Заголовки и характеристики сейчас рассчитаны на категорию «Мобильные телефоны» (iPhone). Для другого товара: обновите `config.models`, `textgen.make_batch` (поле `chars`) и блоки в `filler.fill_one`/`fill_condition` под поля вашей категории (запустите `recon.py` на открытой форме, он сохранит список полей и `data-marker`), затем проверьте одну форму вручную.

## Типичные проверки

- Синтаксис: `.venv\Scripts\python.exe -m compileall -q . -x ".venv"`.
- Тексты без браузера: `cd автовыкладка; ..\.venv\Scripts\python.exe -c "import json,textgen;cfg=json.load(open('config.example.json',encoding='utf-8'));print(textgen.make_batch(cfg,['i17','pm17'])[0]['desc'])"`.
- Фото без браузера: `photos.make_set(<папка с оригиналами>, <временная папка>)`.
- Карта: `..\.venv\Scripts\python.exe карта_метро\build.py`.
- Не запускайте `filler`/`app.py`/`avito_watch.py` из чужой копии репозитория на машине, где уже работает рабочая установка: общие порты и один и тот же профиль Chrome.

Диагностика сбоев: [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).
